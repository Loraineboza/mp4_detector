# MP4 Object Detector

Проект для обнаружения объектов на изображениях и видео с использованием Faster R-CNN с backbone ResNet-50-FPN. Модель обучается на наборе PASCAL VOC 2007 и поддерживает детекцию 20 классов объектов, а также оценку качества по стандартным метрикам компьютерного зрения.

## Возможности

- Обучение Faster R-CNN на PASCAL VOC 2007 с использованием PyTorch.
- Дообучение предварительно обученной модели для распознавания 20 классов объектов.
- Валидация модели во время обучения и сохранение лучших весов.
- Детекция объектов на отдельных изображениях.
- Покадровая обработка видео с отрисовкой ограничивающих рамок и сохранением результата в MP4.
- Вычисление IoU и векторизованной матрицы IoU без циклов по парам рамок.
- Подавление перекрывающихся рамок через NMS (Non-Maximum Suppression) на NumPy.
- Оценка качества детекции по precision, recall и mAP@0.5.
- Фиксированный seed и сохранение конфигурации обучения для воспроизводимости.
- Использование CUDA при наличии совместимого GPU; в противном случае используется CPU.

## Архитектура модели

В основе детектора лежит `fasterrcnn_resnet50_fpn` из `torchvision`. Голова классификации и регрессии ограничивающих рамок заменена под задачу распознавания 20 классов VOC.

Модель распознаёт следующие классы:

`aeroplane`, `bicycle`, `bird`, `boat`, `bottle`, `bus`, `car`, `cat`, `chair`, `cow`, `diningtable`, `dog`, `horse`, `motorbike`, `person`, `pottedplant`, `sheep`, `sofa`, `train`, `tvmonitor`.

Также модель использует служебный класс фона. Общее количество классов — 21.

По умолчанию при инференсе отбрасываются детекции с `confidence score` ниже `0.5`. Порог можно изменить в `img_eval.py` и `mp4_eval.py`.

## IoU и NMS

Основные геометрические операции для работы с ограничивающими рамками реализованы в модуле `detection_metrics.py` и/или библиотеке `detection_utils` при необходимости расширения логики оценки:

- `compute_iou(box_a, box_b)` — IoU для одной пары рамок в формате `[x1, y1, x2, y2]`.
- `compute_iou_matrix(boxes_a, boxes_b)` — векторизованный расчёт IoU для всех пар рамок размера `(N, M)`.
- `non_max_suppression(boxes, scores, iou_threshold=0.5, score_threshold=0.0)` — подавление перекрывающихся рамок по confidence и IoU.

Формула IoU:

```
IoU = intersection_area / union_area
```

где `intersection_area` — площадь пересечения двух рамок, а `union_area` — площадь объединения.

NMS нужен для удаления дублей: если несколько рамок сильно перекрываются и имеют похожие предсказания, оставляется только наиболее уверенная рамка, а остальные подавляются.

## Метрики детекции

Для оценки качества модели используются метрики, привычные для задач object detection:

- `Precision` = TP / (TP + FP)
- `Recall` = TP / (TP + FN)
- `mAP@0.5` — средняя средняя точность (mean Average Precision) при IoU=0.5, рассчитанная по классам VOC-like evaluation.

Эти метрики позволяют оценивать модель не только визуально по картинке, но и количественно по качеству детекции.

### Общее правило расчёта

- `TP` — истинно положительные предсказания (правильный класс + IoU выше порога)
- `FP` — ложноположительные предсказания
- `FN` — пропущенные объекты

Для mAP@0.5 используется стандартный подход VOC: для каждого класса строится PR-кривая, затем вычисляется AP, после чего берётся среднее по классам.

## Подготовка датасета

Проект ожидает, что PASCAL VOC 2007 находится в каталоге `VOCdevkit/VOC2007/` относительно корня репозитория.

Необходимая структура датасета:

```text
VOCdevkit/
└── VOC2007/
    ├── Annotations/
    ├── ImageSets/
    │   └── Main/
    │       ├── train.txt
    │       └── val.txt
    └── JPEGImages/
```

Каталог `Annotations` содержит XML-аннотации объектов, `JPEGImages` — изображения, а `ImageSets/Main` — списки изображений для обучения и валидации.

Загрузчик датасета считывает изображения и аннотации, преобразует классы и координаты ограничивающих рамок в формат, пригодный для обучения `Faster R-CNN`.

## Воспроизводимость и обучение модели

Обучение поддерживает фиксированный seed и сохранение конфигурации запуска:

- `SEED = 42`
- параметры батча, epochs, LR и ранней остановки сохраняются в `model/training_config.json`
- логируются `train_loss`, `val_loss` и текущий learning rate

Запуск:

```bash
python train.py
```

Основные параметры обучения:

- Размер батча: `2`
- Максимальное количество эпох: `30`
- Оптимизатор: SGD с momentum
- Начальный learning rate: `1e-3`
- Планировщик learning rate: `StepLR`, уменьшающий learning rate в 10 раз каждые 5 эпох
- Early stopping: `10` эпох без достаточного улучшения validation loss
- Минимальное улучшение validation loss: `1e-4`

После каждой эпохи выводятся значения `train loss` и `validation loss`. Лучшие веса сохраняются в файл:

```text
model/weights_faster_rcnn_voc.pth
```

Также создаётся конфиг:

```text
model/training_config.json
```

Обучение завершается после достижения максимального количества эпох или срабатывания early stopping.

## Детекция объектов на изображении

Запуск с указанием пути к изображению:

```bash
python img_eval.py img/example.jpg
```

При необходимости можно указать путь к весам модели вторым аргументом:

```bash
python img_eval.py img/example.jpg model/weights_faster_rcnn_voc.pth
```

Если аргументы не указаны, используются пути по умолчанию, заданные в `img_eval.py`.

Скрипт выводит количество обнаруженных объектов, их классы, confidence scores и координаты рамок. Результат отображается на изображении и сохраняется в файл:

```text
result.jpg
```

## Детекция объектов на видео

Запуск с указанием исходного видео:

```bash
python mp4_eval.py videos/example.mp4
```

Чтобы явно указать путь к весам модели:

```bash
python mp4_eval.py videos/example.mp4 model/weights_faster_rcnn_voc.pth
```

Если аргументы не указаны, используются пути по умолчанию, заданные в `mp4_eval.py`.

Видео обрабатывается покадрово. Для каждого кадра модель обнаруживает объекты, после чего скрипт рисует ограничивающие рамки и сохраняет результат в MP4.

Результат сохраняется в файл:

```text
result_video.mp4
```

Для сохранения готовых видео в каталоге `detect_videos/` укажите соответствующий путь в переменной `OUTPUT_PATH` файла `mp4_eval.py`.

```python
OUTPUT_PATH = "./detect_videos/result_video.mp4"
```

Во время обработки нажмите `q` или `Esc`, чтобы остановить выполнение. Если остановить обработку раньше времени, результат будет сохранён только до текущего момента.

## Формат результатов детекции

Для каждого обнаруженного объекта модель возвращает:

- **Класс** — предсказанную категорию объекта.
- **Confidence score** — оценку уверенности модели в предсказанном классе.
- **Bounding box** — координаты ограничивающей рамки в формате `[x1, y1, x2, y2]`, где `(x1, y1)` — левый верхний угол, а `(x2, y2)` — правый нижний.

Confidence score характеризует уверенность модели в предсказании класса и не является непосредственной оценкой качества детектора в целом.

## Проверка и трассировка качества

Для оценки качества составляется набор детекций, затем выполняется сопоставление с ground truth через IoU и порог по IoU (например, 0.5 для mAP@0.5). После этого вычисляются:

- Precision
- Recall
- AP по каждому классу
- mAP@0.5 как среднее по классам

Эта часть особенно полезна при сравнении нескольких моделей, выборе порога confidence и настройке NMS.

## Примечания

- Все команды следует запускать из корня репозитория, чтобы относительные пути к датасету и весам разрешались корректно.
- Для инференса необходимы веса, совместимые с архитектурой модели и используемым списком классов.
- Каталоги `img/`, `videos/`, `model/` и `detect_videos/` предназначены соответственно для входных изображений, исходных видео, весов модели и финальных результатов.
- Проект использует IoU, NMS и детекторные метрики для более объективной оценки качества, а не только визуальной проверки результатов.
- В целях воспроизводимости фиксируются random seed и сохраняется конфигурация обучения.
